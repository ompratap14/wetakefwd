# Internal linking and conversion plan

## Target architecture

```text
Homepage
├── Core service directory
│   ├── AI automation
│   ├── AI development
│   ├── AI agents
│   ├── AI chatbots
│   ├── Business automation
│   └── Custom software
├── Guides
│   └── Supporting commercial and informational articles
├── Selected work
│   └── Relevant service and evidence-backed local page
└── Contact / enquiry
```

Insights should link into this structure contextually, not repeat main-site service copy.

## Link rules by template

### Homepage

- Link the six principal commercial pages.
- Link the guides index and latest useful article.
- Link selected work and contact.
- Do not link every location or every service variation.

### Service page

- Link one to three genuinely related services.
- Link one relevant case study when real evidence exists.
- Link one or two supporting guides or articles.
- Use a CTA matching the service problem, not a generic “contact us” alone.

### Article or guide

- Link the primary service once when the reader reaches an implementation decision.
- Link one related article or guide.
- Link real evidence where it clarifies the advice.
- Avoid repeating exact-match anchors in every article.

### Case study

- Link the most relevant core service.
- Link a local page only when the location and service are accurate.
- Link the contact section with a problem-specific prompt.

## Conversion path

```text
Search query
→ page matching the intent
→ practical explanation
→ relevant proof or assessment
→ service-specific CTA
→ short form or WhatsApp
→ response owner and follow-up
```

## CTA recommendations

| Page type | CTA |
| --- | --- |
| AI automation | “Map one workflow” |
| AI agent development | “Define an agent pilot” |
| WhatsApp/CRM | “Review our lead flow” |
| Custom software | “Scope the smallest useful release” |
| Website/app | “Review the current experience” |
| Guide/article | “Use the assessment” or “Discuss this workflow” |
| Case study | “Plan a similar outcome” without claiming identical results |

## Form and tracking requirements

- Ask only for name, work email or phone, business, service need and short problem description.
- Preserve the friendly success page.
- Track successful submissions, not only submit-button clicks.
- Track WhatsApp, email and phone clicks as separate conversion events.
- Store the landing page and UTM values with the lead where possible.
- Assign an owner and response-time target.
- Never send sensitive operational data through the public form.

## Trust improvements

- Publish accurate team identity and responsibility.
- Add client-approved project dates, scope and measured outcomes.
- Explain data handling, ownership, support and human review.
- Use real project screenshots and original photographs.
- Link to the editorial policy and author profiles from Insights.
- Do not use unverified badges, ratings or testimonials.
